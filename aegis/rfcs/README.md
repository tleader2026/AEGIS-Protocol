# AEGIS RFCs

RFCs define durable protocol behavior. They should include wire format, validation logic, failure modes, security considerations, privacy considerations, interoperability requirements, and migration guidance.

RFC numbers are assigned by maintainers after acceptance into the working group queue.

## Formatting Requirements

Every RFC MUST include:

- BCP 14 conventions
- abstract
- motivation
- wire format
- canonicalization
- validation behavior
- failure modes
- security considerations
- privacy considerations
- interoperability requirements
- registry considerations
- migration behavior

An RFC SHOULD include packet examples and schema fragments unless it is purely procedural.
